# 联运行李追踪工具（Interline Baggage Tracker）

一个纯标准库的命令行工具：根据计划航段和机场扫描记录，解释每件联运行李当前在哪里、在哪个航班上、下一步该做什么。支持装机后在出发机场撤下并重新托运、中转改签、最终机场交付。不联网、不查询真实航班信息。

## 运行

```
go run ./cmd/baggage --state ./state
```

程序从标准输入逐行读取 JSON 请求，向标准输出逐行写出 JSON 响应。每一条成功的变更都会原子写入 `--state` 指定目录下的 `state.json`；退出重开后自动恢复，可继续处理。

## 请求格式

所有请求都带 `op` 字段。

### 登记航班 `register-flight`

```json
{"op":"register-flight","number":"CA123","from":"PEK","to":"SHA"}
```

航班编号唯一，出发与到达机场必须不同。重复登记完全相同的航班幂等成功；同编号不同内容拒绝。

### 托运行李 `register-bag`

```json
{"op":"register-bag","label":"TAG001","segments":[
  {"flight":"CA123","from":"PEK","to":"SHA"},
  {"flight":"MU456","from":"SHA","to":"CAN"}
]}
```

标签唯一；航段序列非空，相邻航段首尾衔接，同一航班不得出现两次，航段必须与已登记航班一致。行李初始位置为首段出发机场。

### 扫描事件 `scan`

```json
{"op":"scan","id":1,"type":"load","label":"TAG001","time":100,"flight":"CA123"}
```

`type` 取值：

- `load` 装机：只能装入“当前位置机场起飞的下一计划航班”；装机后 `loaded` 为该航班。
- `unload` 落地卸机：只能从所装航班卸机，位置移动到该航段目的机场，并把该航段从剩余计划推进到已完成历史。
- `remove` 出发机场撤下：把已装行李退回该航班出发机场，**不**推进计划；撤下后可再次装入同一未完成航班（即装机撤下后重新托运）。已完成航段不能再次装入。
- `deliver` 交付领取：仅当行李在地面且剩余计划为空（到达最终机场）时允许；交付后禁止任何扫描和改签。

事件编号 `id` 全局唯一用于去重，`time` 为整数且同件行李必须严格递增。规则：

- 完全相同的事件重复提交：返回**首次的原结果**（`replayed:true`），不重复改变状态、不追加扫描记录。
- 同一 `id` 但任何字段不同：拒绝。
- 校验失败的请求不更新位置，也**不占用**事件编号，可用同一编号携带正确内容重试。

### 改签 `rebook`

```json
{"op":"rebook","label":"TAG001","segments":[
  {"flight":"CZ789","from":"SHA","to":"CTU"}
]}
```

只允许对地面、未交付的行李改签（已装机必须先 `unload` 或 `remove`）。新计划非空、航班不重复、不含已完成航班，首段必须从行李当前位置起飞并逐段连通。已完成航段历史保持不变。

### 查询 `query` / `query-all`

```json
{"op":"query","label":"TAG001"}
{"op":"query-all"}
```

返回当前位置（地面时）或所乘航班（`loaded`）、已完成航段、剩余计划、`next_action` 下一步操作提示，以及按时间排序的全部扫描记录。

## 响应格式

成功：

```json
{"ok":true,"result":{ ... }}
```

失败（不改变任何状态，后续行继续执行）：

```json
{"ok":false,"error":"原因说明"}
```

## 示例会话

`testdata/smoke_input.jsonl` 与 `testdata/smoke_input2.jsonl` 提供了可直接管道输入的示例：

```
Get-Content testdata/smoke_input.jsonl | go run ./cmd/baggage --state ./state
```

流程覆盖：登记 → 装机 → 撤下 → 重新装机 → 落地中转 →（重开进程）改签后续航段 → 交付。

## 测试

```
go test ./...
```

测试覆盖：多航段中转全流程、非法登记、错误操作顺序、时间戳约束、重复事件幂等与编号冲突、撤下后重新托运、落地后改签（保留已完成历史）、状态持久化往返以及命令行端到端续跑。
